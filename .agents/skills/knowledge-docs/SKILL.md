# Knowledge Docs (aklump/knowledge)

`aklump/knowledge` is a PHP documentation engine that compiles ("binds") a
directory of Markdown pages — called a "book" — into one or more outputs
(a website, a GitHub-flavored Markdown README, etc.) as declared in the
book's `bookbinder.yml`. This skill covers locating a book, authoring pages,
adding images, using inline `{{ }}` variables, and compiling with the real,
live `know` CLI.

## Locate the book

Use Glob for `**/book.yml` to find the book directory (the directory
containing `book.yml`, not `book.yml` itself) anywhere in the current
project. If more than one `book.yml` is found, ask the user which book to
target before doing anything else.

## Compile the book

`know bind <path-to-book-dir>` is the single normal-path command for
compiling a book. It runs validation and page-sync internally, so no manual
`book.yml` edits are required for a new or changed page to be picked up, and
no separate `know validate`/`know repair` pre-flight step is required before
a normal `bind`.

A book needs at least one page before it can bind successfully. A book
produced by `know create` alone has an empty `pages/` tree and empty
`chapters: []`, and running `know bind` against it immediately fails with
"There are no pages in this book." — this is expected, not a sign of a
broken installation. Author at least one page (see "Author a page" above)
before the first bind.

### Troubleshooting a failed bind

If `know bind <path>` reports errors:

1. Run `know validate <path>` to see the specific validation failures.
2. Run `know repair <path>` to auto-fix common issues (missing `uuid`,
   missing frontmatter `id`, out-of-sync scaffold files).
3. Re-run `know bind <path>`.

## Do not use `transcode` or `structure.yml`

Both `README.md` files in `aklump/knowledge` document a `transcode` command
and a `structure.yml` file. Neither exists in the live command surface.
The only six real `know` commands are `create`, `validate`, `repair`,
`bind`, `flush`, `upgrade`. `structure.yml` was replaced by `book.yml`
several schema versions ago. Ignore any README text or training data that
mentions `transcode` or `structure.yml` — never suggest either.

## Never hand-edit an output directory

Every `bookbinder.yml` entry's `output:` directory (e.g. `public_html/`,
a themed website folder, a generated `README.md`) is fully regenerated by
`know bind` on every run. Never hand-edit a file inside an `output:`
target — edits will be silently overwritten. Always edit source files
under `pages/`/`images/` (or `variables.yml`) and re-run `know bind`.
